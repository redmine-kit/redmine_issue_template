# チケットテンプレート

チケットテンプレートは、「新しいチケット」のフォームに、トラッカー、題名、説明、テンプレートで設定する項目の値を入力します。プロジェクトにテンプレートがあると、「新しいチケット」はまずテンプレートの選択画面を開きます。YAML フォームは独自の入力欄を表示し、チケットの作成時に回答を説明に書き込みます。

テンプレートは、プロジェクトのリポジトリの `.redmine/ISSUE_TEMPLATE/` にあるファイル (`.github/ISSUE_TEMPLATE/` は読みません) か、プロジェクトの設定で編集するファイルです。チケットテンプレートはモジュールです。プロジェクトの「設定」›「モジュール」で「チケットテンプレート」を有効にします。

## 権限

| 権限 | 許可すること |
| --- | --- |
| 「チケットの追加」(Redmine の権限) | テンプレートの選択画面とテンプレートの使用 |
| 「チケットテンプレートの管理」 | プロジェクトの設定の「チケットテンプレート」タブ: ファイルのインポート、追加、変更、削除、選択画面の設定、「共有」(メンバーだけ)。空白のチケットを許可していないプロジェクトでの、テンプレートを使わないチケットの作成 |

「管理」›「ロールと権限」でロールに与えます。

## テンプレートの選択画面

「新しいチケット」には、プロジェクトで使えるテンプレートを、「名称」、「説明」、「トラッカー」とともに一覧表示します。テンプレートの名称をクリックすると、そのテンプレートでチケットのフォームを開きます。「空白のチケット」は、テンプレートを使わずにフォームを開きます。`config.yml` で空白のチケットを許可しているときに表示します。「その他の連絡先」には、`config.yml` のリンク (フォーラムやセキュリティの連絡先など) を表示し、新しいタブで開きます。

エラーがあるテンプレートは選択画面に表示しません。空白のチケットを許可していないプロジェクトでは、テンプレートを使わずにチケットを作成できません (「チケットを作成するには、テンプレートを選択してください。」)。ただし、「チケットテンプレートの管理」の権限があるユーザーは作成できます。

## チケットのフォーム

フォームには、選択したテンプレートの値を表示します。トラッカー、題名、最初の説明と、テンプレートで設定する項目の値です。テンプレートで設定した値は、フォームでは変更できません。テンプレートは、フォームの項目を非表示にしたり、必須にしたりすることもできます。

YAML フォームは、その説明と入力欄を、フォームの一番上、説明の位置に表示します。チケットを作成すると、回答は入力欄のラベルごとにチケットの説明になります。アップロードの入力欄のファイルは、チケットに添付します。

## テンプレートの取得元

プロジェクトの「設定」›「チケットテンプレート」タブに、テンプレートの取得元 (「取得元」) を表示します。

- 「リポジトリ」: プロジェクトのメインリポジトリの新しいチェンジセットを Redmine が取得するたびに、デフォルトブランチの `.redmine/ISSUE_TEMPLATE/` のファイルをインポートします。「インポート」で、フォルダーをすぐに読み込みます。プロジェクトの設定で編集したテンプレートは置き換えられます。
- 「GitHub」: Redmine Kit GitHub があれば、デフォルトブランチへのプッシュでフォルダーをインポートします。
- 「プロジェクトの設定」: リポジトリにテンプレートがないプロジェクトは、タブでファイルを追加、変更、削除します。

Redmine は保存したファイルだけを表示します。「新しいチケット」を開いたときにリポジトリを読むことはありません。

## 「チケットテンプレート」タブ

タブには、ファイルを「ファイル」、「名称」、「トラッカー」とともに一覧表示し、エラーがあるファイルに印を付けます。ファイルをクリックすると、その内容、エラーと警告、「プレビュー」(選択画面でのテンプレートの行と、テンプレートで作られるチケットのフォーム) を表示します。エラーがあるテンプレートは選択画面に表示しません。警告 (プロジェクトにないトラッカーなど) があっても、テンプレートは使えます。

ファイルを Redmine で編集するときは、「新しいテンプレート」でファイル (`.md`、`.yml`、`.yaml`、`config.yml`) を追加し、各ファイルを「編集」、「削除」できます。保存するとファイルをチェックし、エラーがあるファイルは保存しません。「プレビュー」は、入力中のテキストを保存せずに表示します。

「テンプレートの選択画面」には、`config.yml` の設定、「空白のチケットを許可」と「その他の連絡先」(各リンクの名称、URL、説明) があります。ファイルを Redmine で編集するときはタブから保存でき、保存すると `config.yml` を作り直します。それ以外のときは読み取り専用で表示し、テンプレートの取得元の `config.yml` で変更します。

「共有」で、プロジェクトのテンプレートをほかのプロジェクトと共有します。値はバージョンの共有と同じです (「共有しない」、「サブプロジェクト単位」、「プロジェクト階層単位」、「プロジェクトツリー単位」、「すべてのプロジェクト」)。自分のテンプレートがないプロジェクトは、テンプレートを共有しているいちばん近いプロジェクトのテンプレートを使います。「共有元」にそのプロジェクトを表示します。

プロジェクトをコピー (「コピー」) するときに、テンプレートもコピーできます。コピーの画面の項目「チケットテンプレート」です。コピーしたプロジェクトのテンプレートは、その設定で編集します。

## テンプレートファイル

- Markdown テンプレート (`.md`): `name` と `about` (必須) と Redmine のキーを書いたフロントマターと、そのあとにフォームの最初の説明を書きます。
- YAML フォーム (`.yml`、`.yaml`): `name`、`description`、`body` (フォームの入力欄: `markdown`、`input`、`textarea`、`dropdown`、`checkboxes`、`upload`) を書きます。`link` のある入力欄は、チケットの項目を設定します。
- Redmine のキー: `tracker`、`priority`、`category`、`fixed_version`、`is_private`、`custom_fields`、`fields` (項目ごとに `shown`、`hidden`、`required`)。
- `config.yml`: 選択画面の設定、`blank_issues_enabled` と `contact_links` です。

テンプレートと回答は Markdown です。テキスト書式には CommonMark Markdown を使ってください (「管理」›「設定」›「全般」)。そうでないときは、タブに警告を表示します。形式の詳細は[テンプレートの形式](https://redmine-kit.github.io/redmine_issue_template/ja/format)を参照してください。
